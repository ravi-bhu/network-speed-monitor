Network usage – Network Speed Monitor

What it does

It puts your current upload and download speed on the taskbar, next to the notification area. Left-click it for the usage report; right-click it for the options.

The readout
Upload on the top line, download on the bottom, updated every second. An optional graph shows the last minute. It follows your taskbar’s light or dark theme.
Adapter
Automatic mode follows whichever adapter carries your internet traffic. You can also pin one adapter and see only its traffic.
Units
Bytes per second by default, or bits. Arrows, or the letters U and D.
Taskbars
The primary taskbar only, or every taskbar if you use more than one monitor.
Start with Windows
On by default. You can turn it off in Settings… on the right-click menu.

The usage report

Left-click the readout to see how much data you’ve used. Pick a period, from today to all time or a custom range, and see it four ways: a summary, a timeline, and totals for each adapter and each Wi-Fi network. Export CSV… saves the period to a file.

It records usage in hourly rows while it runs. Hourly rows are kept for 90 days, then rolled up into one row per day. Traffic while the app isn’t running is not counted, so a day when it was closed shows less than you used.

You can rename or hide an adapter, and clear the history of one adapter, one network or everything.

Privacy

It makes no network connections.

It never connects to the internet or to any other computer. It reads the byte counters Windows already keeps for each network adapter, which is all it needs.

  • No telemetry: no analytics, no crash reports, no update checks, no accounts.
  • Your history and settings stay on your PC, in %LOCALAPPDATA%\NetworkSpeedMonitor, as usage.db and settings.ini.
  • The history holds bytes received and sent per hour, with the adapter’s name and type and the name Windows gives the network (for Wi-Fi, usually its own name). It doesn’t record what you browse, which apps used the traffic, or any content.

The privacy page has the details, including how to delete your data.

Check it yourself

The release workflow stops before publishing anything if the app imports one of the Windows networking libraries: ws2_32, winhttp, wininet or urlmon (the check).

To see what it imports, open the Developer Command Prompt that comes with Visual Studio and run this (the path is right if you kept the default folder):

dumpbin /imports "%LOCALAPPDATA%\Programs\NetworkSpeedMonitor\NetworkSpeedMonitor.exe"

You’ll see iphlpapi.dll in the list. The app uses it to read the adapters’ byte counters.

Install

Version 0.1.0, for Windows 10 or 11. It installs for your user account only, so it doesn’t need administrator rights.

  • Installer for x64, for most PCs NetworkSpeedMonitor-0.1.0-x64-setup.exe
  • Installer for ARM64, for PCs with an ARM processor NetworkSpeedMonitor-0.1.0-arm64-setup.exe

Not sure which? Settings > System > About shows it under System type.

The installers aren’t code-signed yet. Signing has been applied for through SignPath and starts once it’s approved; until then, Windows SmartScreen may warn you before the installer runs. Verify a download explains the warning and how to check the file against the release’s SHA256 hashes.

There’s no winget package yet; it will be listed here once it’s published.

To uninstall, use Installed apps in Settings (Apps & features on Windows 10). The uninstaller asks whether to delete your usage history as well; a silent uninstall keeps it.

For developers

It’s native C++ and Win32, MIT licensed, with a static runtime so there’s nothing else to install. To build it you need Visual Studio 2022 with the C++ workload and CMake 3.25 or newer; the README’s Build section has the commands. Before you send a change, read CONTRIBUTING.md; one of its rules is that the app never gets network code.
